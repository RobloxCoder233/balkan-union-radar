# Balkan Union — Radar & Command Uplink

A fictional air and naval radar network for the Balkan Union, plus a private command dashboard. No real-world data is used or shown.

## Two surfaces

| Route | Surface | Access |
| --- | --- | --- |
| `/` | Air + naval radar scopes (read-only) | Public |
| `/login` | Command key entry | Public |
| `/control` | Alerts, borders, war room, OPS uplink and the CSB feed | Session required |
| `/api/state`, `/api/stream` | Radar snapshot and SSE feed | Public read-only |
| `/api/panel/*` | Meetings, alliances, deliveries, radar orders | Signed session required |
| `/api/csb/*` | Read-only proxy for the Carl's Spelling Bee alert network | Signed session required |

The public radar is generated by the server, so it stays live even when the control panel is closed. Panel orders (condition, drills, siren silence, meetings, convoys, ticker messages) publish over SSE instantly.

## CSB live strike feed

The **CSB** tab in `/control` is an external observation feed. It pulls the live fictional conflict from
`https://csb-air-alert.onrender.com/api/v1` and shows:

- CSB strikes currently airborne toward Dutch Union territory, grouped by target city.
- Incoming vectors with weapon, origin battery, progress and ETA.
- Recent impacts and intercepts.
- CSB launch batteries and weapons.
- A read-only map overlay: strike vectors, target rings, battery diamonds and the external frontline.
- An endpoint console for inspecting every proxied resource as JSON.

The API key stays on the server. The browser calls `/api/csb/<resource>` through a session-gated allow-list;
the key is never sent to the client. Resources include `snapshot`, `stats`, `state`, `alerts`, `alerts/:zone`,
`threats`, `threats/:id`, `strikes`, `history`, `zones`, `weapons`, `launch-sites`, `frontline`, `territories`
and `geometry`.

This feed is **observation only**. It cannot declare war, open a front, move troops or change borders. The
war simulation starts with zero wars and keeps it that way until you declare one in the **War** tab. AI land
offers are also held while no war is active, so the war room stays at `0 fronts` and `No offers` until you
choose to start a conflict.

## Run locally

```bash
npm start
```

Create a `.env` file first (see `.env.example`):

```dotenv
CSB_API_KEY=your-csb-api-key
```

The server loads `.env` on boot. Without `CSB_API_KEY`, the control panel still runs but the CSB tab shows
`NOT CONFIGURED`; the rest of the site is unaffected. `.env` is gitignored and must never be committed.

- Radar: http://localhost:4173/
- Control: http://localhost:4173/control

Without `PANEL_KEY`, the development key is `balkan-command`. The server warns loudly. Never rely on that key on the internet.

```bash
PANEL_KEY="pick-a-long-random-key" SESSION_SECRET="another-long-random-secret" npm start
```

If the radar is opened without the Node server (for example as a local file), it falls back to an offline local simulation. The control panel requires the server.

## Deploy to Render from GitHub

1. Create an empty GitHub repository, then push this folder:

   ```bash
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main
   ```

   `.env`, `.data/`, `.tmp/`, `dist/` and `*.qoder.site` are ignored, so no keys are pushed.

2. In Render, choose **New → Blueprint** and point it at the repository. `render.yaml` creates one Node
   web service (`balkan-union-radar`, free plan, health check `/api/health`).
3. Render prompts for the two `sync: false` variables. Set:
   - `PANEL_KEY` — the command key you will type at `/login`. Pick a long random string; this is your password.
   - `CSB_API_KEY` — your CSB alert-network key. Leave it blank to run everything except the CSB tab.
   `SESSION_SECRET` is generated by Render automatically; `NODE_ENV=production` is set for you.
4. After the deploy is live, open `https://<service>.onrender.com/control`, enter the command key, and use
   the **Ops** and **CSB** tabs. The public radar is at `https://<service>.onrender.com/`.
5. Keep the keys private. Change them in Render's environment if they ever leak; sessions are signed with
   `SESSION_SECRET`, so rotating that secret logs everyone out.

Notes:

- Free Render services spin down after inactivity; the first request may take a few seconds.
- The filesystem is ephemeral. Meetings, alliances and deliveries survive restarts via `.data/panel-state.json`, but a redeploy resets them unless a Render disk is mounted.
- The radar simulation itself is regenerated on every boot, which is intentional.
- Set a custom domain in Render if desired; the server does not hard-code a hostname.

## Security

- `PANEL_KEY` and `SESSION_SECRET` are required in production; the server refuses to boot without them when `NODE_ENV=production`.
- Sessions are HMAC-signed, `HttpOnly`, `SameSite=Strict`, and marked `Secure` in production.
- Panel writes are same-origin checked and rate limited on login.
- The CSB API key is server-side only. `/api/csb/*` requires a session, allow-lists resources and query keys, refuses non-HTTPS upstreams, and never forwards the key to the browser.
- Only allow-listed static paths are served; `control.html` cannot be fetched directly.
- `.data/` and `.env` are never served.
- Every figure, unit, country and leader shown is fiction.
